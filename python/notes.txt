The Python language was named after Monty Python, not the Python reptile!
The Python interpreter is usually situated in `/usr/bin/local` from where we generally run Python programs.
In the Python console we can access the last used expression with _
UTF-8 is the default encoding for Python files.

Just like in Ruby, almost everything in Python is an object.
A class is just a custom way to denote a data type of our own. That data type in turn uses the primitive data types.
`self` is always the first argument which goes to any method in a class. `self` is the actual instance of a class which is being operated upon.
The `__init__` method is the constructor method in Python. It's also a Magic method.
Magic methods are also known as Dunder methods which stands for Double Underscore methods.
Any method which appears inside a class with __ at the beginning and end is known as a Magic method/Dunder method.
The __str__ dunder method has got to be more user friendly whereas the __repr__ method needs to be more dev friendly.

Don't use `assert` for assertions, because they can be turned off when we run our code in Optimized mode.
We can run Python in Optimized mode with `python3 -O`.
Instead we should `raise` TypeError and ValueError separately for implementing type and value validations.
Just like TypeScript, we can use type annotations in Python to make it behave a bit more stricter than the flexibility it generally allows.
For Example:
  def __init__(self, name: str, price: float, quantity: int = 0) -> None:

We can directly access class variables from objects themselves, because, the object looks up the hierarchy of the scope and looks up to find out something which is not found within.
Similar to magic methods we also have magic attributes, which are denoted by __ as well. An example is `__dict__` which tells us the attributes associated to that object. It looks at those attributes at the immediate level only. Not up the hierarchy.

We can add class methods for Python classes using `@classmethod` decorator. Over here, the first arg which goes for the method isn't `self`, instead it's `cls`, which tells that we are referencing the class and not the object to be instantiated.
A class method works with the class and can create or modify class-level data. It's commonly used for alternative constructors, such as loading objects from a CSV file.

A static method is simply a function placed inside a class because it's logically related to that class.
Static methods don't take self or cls as the first arg, because they are generally independent of a class's state. It's denoted with `@staticmethod` decorator.

Through basic inheritance, we can simply make attributes and methods inherited into the sub class from the parent class.
Python supports both - Single & Multiple inheritance. But there's no strict convention decided which to use. We generally prefer simple inheritance hierarchies, use composition when it fits better, and use multiple inheritance selectively.
  Single Inheritance - for a genuine "is-a" relationship
  Multiple Inheritance - for a genuine "has-a" relationship

Following are the types of arguments which we can use in Python:
  Positional arguments: Item("Phone", 1000, 5) => Traditional, order matters
  Keyword arguments: Item(name="Phone", price=1000, quantity=5) => Order doesn't matter, matches based on arg & param name
  Arbitrary keyword arguments: def func(**kwargs) => Takes in a dynamic number of arguments and Python converts them into a dictionary for access inside the func

Decorators add extra functionality to any function based on the type of the decorator we attach to it.
For example, to add getters and setters, we need to use @property, @field_name.setter decorators respectively. Getter, Setter methods are more exclusively used for adding validations while the attributes are being changed or initialized.
There's also this convention of using `__` before field names in getter and setter to avoid it being overriden from the outside.

4 Pillars of OOP:
  Encapsulation:
    Hide data, expose only essential. Hide both - attributes & methods.
    Bundle data and methods together inside a class.
    Control how an object's internal state is accessed or modified.

  Abstraction:
    Hide the complexity or unnecessary details and expose a simple interface to interact with.
    In Python we don't have access modifiers like private or public which we generally have in other programming languages.
    But here, we have to follow the convention of prefixing __ in front of attributes or methods to keep them private.
    For protected, meaning sub class usage, we have to prefix a single _ for attributes and methods.
    Please note that in Python, nothing is completely inaccessible, those are just ways to communicate to devs for quick understanding. There are ways to bypass it.

  Inheritance:
    Allows a class to reuse or extend the behavior of another class.
    Python supports single and multiple inheritance.

  Polymorphism:
    Allows different objects to respond to the same operation in their own ways.
    We have the common use case of overriding the Dunder methods in the individual classes.
    It's basically for responding to different data types with the same function. Best example is the `len` function.
    In Python, this commonly works through duck typing and method overriding.
    It's especially valuable for sub classes, where we have a base implementation of a method and then change the implementation based on the sub class requirements.

C language integration:
  A powerful feature of Python is that we can write performance critical stuff in C and then integrate with Python programs!
  For Example, we have written basic calc functions in the file `basic_calc.c` then we have compiled it as a `.so` - Shared Object file and then called that as a library in Python.
    gcc -shared -fPIC -o basic_calc.so ./basic_calc.c
  Then we can simply outsource critical stuff to C, which is the most performant language.
  Similarly, we can also inegrate Go if required. The choice is ours.

Fun Fact:
  We can also integrate C in Go, Java, NodeJS, Browser JS with respective APIs or compatibility tools.
    Node.js => Node-API native addons
    Browser JS => WebAssembly, Tools such as Emscripten compile C into WebAssembly, which JavaScript can load and interact with.
    Java => Java uses JNI (Java Native Interface) to call native C or C++ code.
    Go => cgo to include and integrate C language code.
  This is also called Foreign-function interfacing (FFI), native extensions, and language interoperability.
  This is so Revolutionary!

Python Strings are immutable. Lists are mutable. But like lists, strings can be accessed via index, but not modified.
Multiple line string literals can start be denoted with """, it can also be denoted with ''', but the convention is """
The last character of string begins from -1. Just like Golang, we can slice strings using [:] syntax.
For example: word[:2], word[0:2], word[2:5], word[4:]

Python Lists similar to strings can be indexed and sliced. Lists are like arrays which we have in JS. They can contain elements of different data types.
Lists in Python are pass by reference and not pass by type. So, when we do
rgb = ['Red', 'Green', 'Blue']
rgba = rgb
rgba.append('Alpha')
print(rgb)
>>> ['Red', 'Green', 'Blue', 'Alpha']

To maintain a copy of list, we need to use the following:
wrestlers = ['Stone Cold', 'The Rock', 'The Undertaker', 'Triple H']
attitude_era = wrestlers[:]

In Python we can make multiple assignments in a single line:
a, b = 0, 1
In multiple assignments, the expressions on the RHS are evaluated and assigned from Left to Right.
